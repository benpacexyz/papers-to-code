# Suggested WebPhish Training Update

## Recommendation

Replace the position-dependent flattened convolution output with masked global max pooling and use the following configuration:

| Setting | Current | Suggested |
| --- | ---: | ---: |
| Embedding dimension | 16 | 32 |
| Convolution channels | 16 | 32 |
| Kernel size | 8 | 12 |
| Pooling | Width-2 max pool, then flatten | Masked global max pool |
| Dense layers | 10, 10 | 16 |
| Dropout | 0 | 0.10 |
| Optimizer | Adam | AdamW |
| Learning rate | 0.0015 | 0.003 |
| Weight decay | 0 | 0.0008 |
| Batch size | 32 | 64 |
| Epochs | 20 | 6 |
| Positive-class weight | 1.0 | 1.0 |
| Decision threshold | 0.5 | 0.5 |

Keep `max_doc_length=1898`, `MIN_WORD_COUNT=10`, and the existing training/test parquet files unchanged.

The suggested model is:

1. Token embedding with 32 dimensions.
2. One 1D convolution with 32 filters and kernel size 12.
3. GELU activation and masked global max pooling over valid, non-padding positions.
4. Layer normalization, a 16-unit GELU layer, 10% dropout, and one output logit.

Global pooling lets a phishing-related pattern contribute regardless of where it appears in the HTML. It also removes the large location-specific flattened head, which is prone to memorizing positions. The broader and refined searches found no consistent benefit from multi-kernel or stacked-convolution models, so the simpler single-convolution design is preferred.

Sort retained vocabulary tokens before assigning indices. The current helper builds indices from a `set`, so token IDs can change with Python hash order between processes even when the training seed is fixed.

## Tuning Method

- Only `html_train.parquet` was used for architecture and hyperparameter selection.
- After the source-equivalent 1,898-token truncation and deduplication, 27,128 training rows remained.
- A 20% confirmation partition was held outside Optuna. Splits were stratified by label and file source.
- Each of 18 completed trials was scored on two separate inner validation splits. There were 16 unique configurations because two queued trials were repeated when the study resumed. The objective was `0.35 * accuracy + 0.65 * F1`.
- The search covered a simple global-pooling CNN, parallel multi-kernel TextCNNs, and stacked CNNs, plus capacity, dropout, batch size, learning rate, weight decay, pooling, and positive-class weighting.
- Early stopping was used inside tuning. The final full-data epoch count was fixed before test evaluation.
- `html_test.parquet` was not read by the tuning script, and the 0.5 threshold was not tuned.

The supplied paper uses cross-validation and early stopping and reports little gain from adding more convolutional or fully connected layers. The experiment results here point in the same direction: pooling and regularization mattered more than added depth.

The suggested configuration was trained five times from scratch with fresh operating-system-random seeds. Values are percentages.

| --- | ---: | ---: | ---: | ---: |
| Accuracy | 94.51 +/- 0.56 | 96.24 +/- 0.30 | 95.98-96.72 | +1.73 pp |
| Precision | 92.36 +/- 3.11 | 95.64 +/- 2.02 | 93.29-98.66 | +3.27 pp |
| Recall | 90.61 +/- 2.95 | 92.62 +/- 1.74 | 89.69-94.30 | +2.01 pp |
| F1 | 91.40 +/- 0.84 | 94.07 +/- 0.45 | 93.70-94.83 | +2.67 pp |
| FPR | 3.63 +/- 1.63 | 2.04 +/- 0.99 | 0.58-3.22 | -1.60 pp |

Every suggested-model run exceeded every baseline run on both accuracy and F1. The mean accuracy now slightly exceeds the 96.06% value documented in the source, but mean F1 remains below the documented 96.03%.

Mean training time in this environment was 16.65 seconds per suggested run versus 54.96 seconds per baseline run. This comparison includes the reduction from 20 to 6 epochs.

## Generalization Checks and Caveats

The data audit found that 97 of 2,289 test rows (4.24%) have the same first 1,898 tokens as a training row. Only two test rows are full-document duplicates. To reduce the risk that this overlap explains the improvement, metrics were also calculated on the 2,192 test rows with a novel 1,898-token prefix:

| Metric | Baseline mean +/- SD | Suggested mean +/- SD | Mean change |
| --- | ---: | ---: | ---: |
| Accuracy | 94.39 +/- 0.58 | 96.20 +/- 0.34 | +1.81 pp |
| F1 | 90.85 +/- 0.90 | 93.76 +/- 0.52 | +2.90 pp |
| FPR | 3.64 +/- 1.67 | 2.02 +/- 1.01 | -1.61 pp |
| FNR | 10.01 +/- 3.14 | 7.78 +/- 1.85 | -2.24 pp |

The improvement remains on the stricter subset, and seed spread is smaller than the baseline. This supports, but does not prove, out-of-distribution generalization.

There are two remaining limitations:

- File source and label are partly confounded. For example, all provided PhishTank training rows are phishing, and its test subset has only 25 rows. Per-source metrics are therefore too small or imbalanced to support strong deployment claims.
- No independent `html_valid.parquet` or new external dataset was available. Future changes should not be tuned further against the current test file; use a genuinely new, source-separated holdout for the next decision.

## Implementation Notes

- Preserve an internal validation split from training for early stopping and never select parameters or thresholds on the test set.
- Mask padded convolution positions before global pooling.
- Use `BCEWithLogitsLoss`, gradient clipping at 1.0, and a fixed 0.5 threshold.
- Mixed-precision training is optional for speed and was used in these scratch experiments.
- Save the vocabulary ordering, model configuration, selected epoch count, and actual random seed with each trained artifact.

Reproducible details are in `agent/results/baseline_runs.json`, `agent/results/tuning_results.json`, and `agent/results/final_stability_runs.json`.
